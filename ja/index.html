失敗パターン

修正はチャット履歴の中で消えていきます。

有用な修正は小さなポストモーテムです。Rulewrightは、その教訓が別のセッション履歴に埋もれる前に、再利用できるプロジェクト指示へ変換します。

仕組み

修正済みセッションからプロジェクトルールへ。

01

セッションを読む

エージェントが修正されたCodexスレッドまたはトランスクリプトから始めます。

02

教訓を検出する

スコープ、検証、コミュニケーション、ローカライズ言語プロファイルの信号を分類します。

03

パッチを提案する

AGENTS.md、CLAUDE.md、Cursor rules、Copilot instructionsに入る狭いルールを提案します。

例

実際の修正に基づくルール。

スコープ制御

全体のレイアウトを変えたのが問題です。crop編集だけ直してほしかった。

+ 編集前に要求された最小範囲を固定する。
検証

テストを実行せずに直ったと言わないで。

+ 完了と言う前に報告された動作を検証する。
言語プロファイル

日本語で修正したなら、ルールも日本語で残すべきです。

+ 検出したユーザーの言語でルールを書く。

インストール

エージェントがすでに読むルールの場所で使う。

一度cloneしてから、使いたいエージェントワークフローにRulewrightをインストールします。

Codex

npm run install:codex

Rulewrightを個人用Codexプラグインとmarketplace項目としてインストールします。

Claude Code

npm run install:claude

Rulewright skillをClaude Code skillsフォルダへコピーします。

Cursor

npm run install:cursor -- /path/to/project

.cursor/rules/rulewright.mdcにrepository ruleを追加します。

GitHub Copilot

npm run install:copilot -- /path/to/project

.github/copilot-instructions.mdのRulewrightブロックを更新します。

オープンソース

すでに支払った修正を失わない。

Rulewrightは、具体的なセッション証拠からエージェントの振る舞いを改善したいチーム向けの初期オープンソースプロトタイプです。
